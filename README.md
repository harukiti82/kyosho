# 挟将（きょうしょう）

オセロの盤で、挟んだ相手の駒を取って自分の持ち駒にする二人対戦ゲーム。取った駒の数字（歩1・金3・飛5）の合計が相手へのダメージになり、体力 20 を先に削り切った方が勝ち。
ルールは [RULES.md](RULES.md)（v1.0）を参照。

1. 持ち駒を空いているマスならどこにでも置ける
2. 置いた駒と自分の駒で挟んだ相手の駒を取って、自分の持ち駒にする
3. 取った駒の数字の合計が相手へのダメージ
4. 体力 0 以下で負け（80 手で終われば体力の多い方の勝ち）

## ブラウザで遊ぶ（`web/`）

公開版: **https://harukiti82.github.io/kyosho/**（main に push すると GitHub Actions で自動デプロイ）

手元で動かす場合:

Node.js 22.12 以上が必要（Vitest 5 の要件。遊ぶだけなら Vite 8 の 20.19 以上でも可）。

```sh
cd web
npm install
npm run dev        # 表示された URL（既定 http://localhost:5173）を開く
```

ブラウザ版は**ルールを組み合わせて遊び比べる試遊版**。対局前の設定画面で次の項目を選ぶ（各項目は独立に組み合わせられる）。

| 項目 | 選択肢 |
|---|---|
| 挟んだ駒を | 裏返す（オセロ。挟めるマスにしか置けない）／取って持ち駒にする（空きマスならどこでも置ける） |
| 強さ制限 | なし／置いた駒より数字が大きい駒を含む列は返せない（取れない） |
| 挟める方向 | 全方向（8 方向）／駒ごと（置いた駒の矢印の方向の列だけ返せる。歩↕ 横↔ 銀✱ 角✕ 飛✚ 金✱） |
| ダメージ | 返した駒の数字の合計／最大値＋枚数÷4 |
| 端の駒の力 | なし／攻撃に上乗せ（返した列ごとに、反対端の自分の駒の数字もダメージに足す） |
| 回復 | なし／挟んだ両端の平均／両端の低い方−1（複数方向は最大の 1 方向分） |
| 体力・駒・手数上限 | 先手・後手の体力（5〜200）、歩・横・銀・角・金・飛 の個数（0〜40）と数字（1〜20）、手数上限（0 = なし） |
| 隠し王（読み合い） | なし／あり。ありなら、王を返されたときの罰（体力−N（1〜200）／即負け）と指定期限（各自の最初の 1〜20 手） |

- プリセット: **v0.4**／**v1.0（取る）**（既定）／**v2案（強い駒は返せない）**／**原案**／**隠し王**／**方向駒**／**拠点**。選んだ後に個別に変えられる
- 方向駒: 駒ごとに挟める方向が違う（歩↕縦・横↔横・角✕斜め・飛✚縦横・金✱全方向。数字は 歩1 横1 角3 飛3 金5）。盤上の駒と持ち駒に方向のアイコンが付き、持ち駒を選び替えるとその駒で返せるマスだけに印が付く。予測と「!」も駒の方向で計算する
- 拠点（端の駒の力）: 方向駒に「攻撃に上乗せ」を足したもの（体力 125・130）。挟むのに使ったもともと盤上の自分の駒（列の反対端）の数字もダメージに足すので、強い駒は置いた後も何度も攻撃の拠点になり、返されると相手の拠点になる。予測中は上乗せに使う端の駒を青枠と「+数字」で示し、予測と棋譜にダメージの内訳（返した駒 ＋ 端の駒）を出す
- 隠し王: 自分の最初の数手のうち 1 手で、置く前に持ち駒欄の「この駒を王にする」を押すと、その駒が相手に見えない王になる（期限の手までに決めなければ期限の手の駒が自動で王）。王を返されたら通常のダメージ＋罰で、王は公開されて以後ふつうの駒。CPU 対戦では自分の王に常に「王」の印、2 人対戦では「自分の王を確認」を押している間だけ表示
- 設定は URL のクエリに入る。「この設定の URL をコピー」で共有でき、開くと同じ設定が入った設定画面から始まる（不正な値は既定値に戻す）
- 対局画面のルールカードは今の設定から自動で作る 3〜8 行の文。予測（返せる・取れる駒の赤枠とダメージ・回復）、相手に次の 1 手で返されうる自分の駒の「!」、持ち駒、体力バー、棋譜は全設定で動く
- モード: CPU 対戦（先手・後手を選べる）／2 人対戦（同じ端末で交互）。スマホはタップ 2 回で確定（1 回目は予測）
- CPU は全設定共通の 2 手読み（自分の (ダメージ＋回復) − 相手の最善応手の (ダメージ＋回復)、同点はランダム。ダメージは端の駒の上乗せ込み）。隠し王では相手の王の「候補」（期限内に置かれ、まだ返されていない駒）だけを見て罰の期待値を足し、自分の王を返される応手には罰を足す
- 終局判定: 体力 0 で即負け（隠し王の罰が即負けなら、王を返された時点でも負け）。手数上限・両者パスで終わったら 体力 → 石数 の多い方の勝ち

### 開発用コマンド

| 用途 | コマンド（`web/` で実行） |
|---|---|
| 本番ビルド（`web/dist/`、相対パスなのでどの静的ホスティングにも置ける） | `npm run build` |
| ビルド結果の確認 | `npm run preview` |
| 型チェック | `npm run typecheck` |
| ユニットテスト + Python エンジン（v0.4 / v1.0 / v2 案）との整合テスト | `npm test` |
| ヘッドレスブラウザでの対局テスト（初回は `npx playwright install chromium`） | `npm run e2e` |
| バランス確認（2 手読み同士。引数: 局数・プリセット・体力 "先手,後手"） | `npm run balance -- 400 king`（方向駒は `400 dir`、拠点は `400 anchor`） |

整合テストの棋譜（`web/test/fixtures/replays.json`）は `python3 sim/export_replays.py` で再生成できる（`sim/kyosho.py`・`sim/capture.py`・`sim/gate.py` の 3 本を、それぞれ対応するプリセットの設定で再生する）。
シミュレーターのルールを変えたら TypeScript 側も直し、棋譜を作り直してから `npm test` を通す。

## バランス検証（`sim/`）

Python 3 のシミュレーター（標準ライブラリのみ）。v1.0 は `sim/capture.py` / `sim/check_capture.py`、v2 案（強い駒は返せない）は `sim/gate.py`。
使い方は [RULES.md のシミュレーター節](RULES.md#シミュレーター) を参照。旧ルール v0.4 は [docs/RULES-v0.4.md](docs/RULES-v0.4.md) と `sim/kyosho.py` に残している。
