# 挟将（きょうしょう）

オセロの盤で、挟んだ相手の駒を取って自分の持ち駒にする二人対戦ゲーム。取った駒の数字（歩1・金3・飛5）の合計が相手へのダメージになり、体力 20 を先に削り切った方が勝ち。
ルールは [RULES.md](RULES.md)（v1.0）を参照。

1. 持ち駒を空いているマスならどこにでも置ける
2. 置いた駒と自分の駒で挟んだ相手の駒を取って、自分の持ち駒にする
3. 取った駒の数字の合計が相手へのダメージ
4. 体力 0 以下で負け（80 手で終われば体力の多い方の勝ち）

## ブラウザで遊ぶ（`web/`）

公開版: **https://harukiti82.github.io/kyosho/**（main に push すると GitHub Actions で自動デプロイ）。Cloudflare の **https://kyosho.rukiharukichi.com/** への移行を準備中（下の「オンライン対戦サーバーと Cloudflare での公開」）

手元で動かす場合:

Node.js 22.12 以上が必要（Vitest 5 の要件。遊ぶだけなら Vite 8 の 20.19 以上でも可）。

```sh
cd web
npm install
npm run dev        # 表示された URL（既定 http://localhost:5173）を開く
```

ブラウザ版は**ルールを組み合わせて遊び比べる試遊版**。開くとメニューが出る。

- メニュー: 「CPU対戦」→ 強さ（イージー／ノーマル／ハード）を選ぶとすぐ始まる。「マルチ」→「この端末で 2 人」か「オンライン」。「設定」でルールと手番を変える。どれも設定で保存したルール（変えなければ「標準」）で始まり、対局前に設定画面は出ない。メニューの下の「ルール 名前」を押すとルール詳細。対局中は右上の「メニュー」で戻れ（「対局に戻る」で続きから）、終局画面からも戻れる
- 遊び方（チュートリアル）: メニューの「遊び方」から、用意した小さな局面で 1 手ずつ打って標準ルールを覚える。挟む → ダメージ（体力 0 で勝ち）→ 駒の向き → 持ち駒 → 反対側の駒（挟んだ反対側の自分の駒の数字も足す）→ 回復 → 王を決める → 王を裏返す → 予測を読む（ダメージの数字・「!」・オセロの点線の枠）の 9 ステップと、最後に CPU（イージー・制限時間なし）との実戦。打つマスは光る輪（1 マスなら矢印も）、選ぶ駒・押す王は駒台で光る。違う手は打たずにヒント、正解すると何が起きたかをそのとき盤で起きた数字で説明して「次へ」。ステップ中は CPU も制限時間も動かない。進み具合はこの端末に保存し（使えなければ覚えないだけ）、メニューに「おすすめ」「つづき N/10」「クリア済み」と出る。上の石で開いたことのあるステップへ戻れる。途中で「メニュー」に出ても「対局に戻る」か「遊び方」で続きから
- CPU の強さ: イージーは相手の応手を読まずにその手のダメージ＋回復だけで選び、35% の確率で適当な手を打つ。ノーマルは従来の 2 手読み（自分の得点 − 相手の最善応手の得点）。ハードは 2 手読みの上位 8 手について、相手の応手（得点の上位 6 手）の後の自分の最善手まで 2 手読みで読み、相手の体力を削り切る手・削り切られる応手を最優先で扱う。標準で 400 局ずつ（先手・後手を入れ替えて）対戦させた勝率は ノーマル対イージー 87.5%・ハード対ノーマル 67.0%・ハード対イージー 89.2%。1 手の思考はハードで平均約 3ms（`npm run balance -- vs 400 std normal hard` など）
- 1 手の制限時間: 手番が来るたびに戻る 1 手ごとの持ち時間。残りは手番の人の名札の時計（10 秒以下で琥珀、5 秒以下で赤）で、切れると置ける手（駒の種類も含む）から 1 手が自動で打たれ、棋譜に「（時間切れ・自動）」、トーストで知らせる（隠し王の期限の手なら置いた駒が自動で王になる）。CPU 対戦はあなたの手番だけで、既定は強さに合わせてイージー なし・ノーマル 45 秒・ハード 20 秒（メニューの強さのボタンに表示）。マルチ（この端末で 2 人・オンライン）は既定 45 秒。設定メニューの「1 手の時間」で CPU 対戦は おまかせ（強さに合わせる）／なし／20／45／90 秒、マルチは なし／20／45／90 秒に変えられる（ルールではないので URL には載らない）。着手の大きな演出の間・メニューを開いている間・CPU が考えている間は進まない。タブを裏に回しても時刻の差で数えるので、戻ったときに経過した分だけ減っている。オンラインは部屋を作った人の設定でサーバーが計り、相手が切断中でも進む
- 設定メニュー: 次の項目を選んで「保存」すると次の対局から使う（この端末のブラウザに保存。保存が読めない・壊れているときは標準。「やめる」で保存しない）。各項目は独立に組み合わせられる

| 項目 | 選択肢 |
|---|---|
| 挟んだ駒を | 裏返す（オセロ。挟めるマスにしか置けない）／取って持ち駒にする（空きマスならどこでも置ける） |
| 強さ制限 | なし／置いた駒より数字が大きい駒を含む列は返せない（取れない） |
| 挟める方向 | 全方向（8 方向）／駒ごと（置いた駒の矢印の方向の列だけ返せる。歩↕ 横↔ 銀✱ 角✕ 飛✚ 金✱） |
| ダメージ | 返した駒の数字の合計／最大値＋枚数÷4 |
| 端の駒の力 | なし／攻撃に上乗せ（返した列ごとに、反対端の自分の駒の数字もダメージに足す） |
| 回復 | なし／挟んだ両端の平均／両端の低い方−1（複数方向は最大の 1 方向分） |
| 体力・駒・手数上限 | 先手・後手の体力（5〜200）、歩・横・銀・角・金・飛 の個数（0〜40）と数字（1〜20）、手数上限（0 = なし） |
| 隠し王（読み合い） | なし／あり。ありなら、王を返されたときの罰（体力−N（1〜200）／即負け）と指定期限（各自の最初の 1〜20 手） |

- プリセット: **v0.4**／**v1.0（取る）**／**v2案（強い駒は返せない）**／**原案**／**隠し王**／**方向駒**／**拠点**／**標準**（既定）。選んだ後に個別に変えられる
- 標準（既定）: 方向駒＋端の駒の力（攻撃に上乗せ）＋隠し王（最初の 7 手のうち 1 手・返されたら体力−30）、回復は挟んだ両端の低い方−1、体力 129・130（2 手読み同士で先手勝率が 50% に最も近い値）、持ち駒は 歩10 横10 角4 飛3 金2。クエリなしで開くとこの設定から始まる
- 方向駒: 駒ごとに挟める方向が違う（歩↕縦・横↔横・角✕斜め・飛✚縦横・金✱全方向。数字は 歩1 横1 角3 飛3 金5）。盤上の駒と持ち駒に方向のアイコンが付き、持ち駒を選び替えるとその駒で返せるマスだけに印が付く。予測と「!」も駒の方向で計算する
- 拠点（端の駒の力）: 方向駒に「攻撃に上乗せ」を足したもの（体力 125・130）。挟むのに使ったもともと盤上の自分の駒（列の反対端）の数字もダメージに足すので、強い駒は置いた後も何度も攻撃の拠点になり、返されると相手の拠点になる。予測中は上乗せに使う端の駒を青枠と「+数字」で示し、予測と棋譜にダメージの内訳（返した駒 ＋ 端の駒）を出す
- 隠し王: 自分の最初の数手のうち 1 手で、置く前に駒台の右端の王の駒（「あと N 手」）を押すと、その駒が相手に見えない王になる（期限の手までに決めなければ期限の手の駒が自動で王）。王を返されたら通常のダメージ＋罰で、王は公開されて以後ふつうの駒。CPU 対戦では自分の王に常に「王」の印、2 人対戦では駒台の王の駒（押して確認）を押している間だけ表示。王の場所は名札に王の駒の形とマス名で出る
- 設定は URL のクエリに入る（保存したとき・対局を始めたときにアドレスバーへ載る）。設定メニューの「URL をコピー」で共有でき、開くとメニューにその設定が入る（保存した設定より優先し、保存は書き換えない）。URL は v1.0（取る）を基準にした差分で、載っていない項目・不正な値は v1.0 の値にする（既定を標準に変える前に共有した URL も同じ設定で開ける）
- 対局画面のルールカードは今の設定から自動で作る 3〜8 行の文で、盤の横（スマホは盤の下）の引き出しの「ルール」タブにある（PC は開いて始め、スマホはタブを押すと開く。予測の詳しい文・棋譜・印の見かたも同じ引き出しのタブ）。予測（返せる・取れる駒の赤枠とダメージ・回復のバッジ、狙ったマスの吹き出しの内訳と警告）、相手に次の 1 手で返されうる自分の駒の「!」、普通のオセロなら置けるマスの点線の枠（駒の種類・方向・強さを考えない参考表示。操作できる手番だけ）、持ち駒（駒台と名札）、体力ゲージ、棋譜は全設定で動く
- モード: CPU 対戦（自分の手番は設定メニューでランダム／先手／後手。既定はランダム。ランダムは対局を始めるたびに抽選し、メニューから始め直しても・再戦でも引き直して、開始時に「抽選で先手になりました」などと出す。後手なら CPU の初手から始まる）／2 人対戦（同じ端末で交互）／オンライン（招待リンクで遠隔の相手と。下の「オンライン対戦」）。スマホはタップ 2 回で確定（1 回目は予測）
- オンライン対戦: メニューの「マルチ」→「オンライン」で、設定のルールと自分の席（設定メニューの手番の「オンライン」。部屋を作る側の席で、ランダム（既定）／先手／後手）で部屋を作り、招待リンクが出る。リンクを相手に送り（コピー・スマホは共有も）、相手が開いて「参加する」を押すと対局が始まる。ログインなし。手はサーバーが確かめて両者に配るので、自分の手番だけ打てる。木枠の下の縁に相手の接続（接続中／切断中）、自分の通信が切れたら「再接続中…」を出し、自動でつなぎ直す（再読み込みしても同じ席に戻る）。隠し王では自分の王に「王」の印、相手の王の候補（相手が期限内に置き、まだ返していない駒）に「?」の印と、相手の名札に「候補N」。終局後の「新しい部屋で再戦」は同じルール・同じ席で部屋を作り直す（招待リンクを送り直す）。サーバー（`/api`）に届く公開先（https://kyosho.rukiharukichi.com/ ・ローカルの `cd server && npm run dev`）でだけ入口が出る。GitHub Pages 版と `npm run dev`・`npm run preview` 単体では出ない
- 手応えの演出（ルールには影響しない）: その手のダメージ（端の駒の上乗せ・隠し王の罰を含む）を**受けた側の体力上限**で割った割合で 4 段階。小（5% 未満）は数字だけ、中（5% 以上）は数字を大きく「ナイス！」、大（10% 以上）は盤の揺れと光の粒で「会心！」、特大（20% 以上、または王を返した手）は返す駒を順にめくる溜めの後に画面全体が光って「痛恨！」（王を返した手は「王を討った！」）。CPU から受けた中以上は赤い被弾の演出（画面の縁が赤く脈打つ）。大・特大の演出中（最大 1.5 秒）は次の入力と CPU の着手を待たせる。OS の「視差効果を減らす」（動きを減らす）設定では揺れ・粒・溜め・発光を省いて数字と文言だけ
- 効果音: Web Audio API で合成（音声ファイルなし）。置く・返す・ダメージの段階ごとの音。画面右上のスピーカーのボタンで消音（ブラウザに保存）。最初に画面を操作するまでは鳴らさない
- 決着の演出（ルールには影響しない）: 最後の一手の演出のあと、終局画面の前に出す（最大 2.5 秒。タップ・クリック・Enter で飛ばせる）。CPU 対戦で勝てば紙吹雪と暖色の光で「勝利！」とファンファーレ、負ければ画面の色が落ちて静かに沈む「敗北…」と低い音、引き分けは穏やかな「引き分け」。副題に決着の理由（体力 0 で撃破／体力判定／石数／王を討った手）。接戦で負けたとき（体力判定の差、または体力 0 で負けたときの相手の残り体力が自分の体力上限の 10% 以下・石数負け）は「惜しい！ あと 3 点だった」などを添え、終局画面の「再戦」を強調する。2 人対戦は敗北の演出を出さず、勝った側の駒色で「先手の勝ち！」。動きを減らす設定では紙吹雪・発光・沈みを省いて文字だけ
- 終局画面の成績: 最大ダメージとその内訳・「会心」以上の回数・端の駒の上乗せの合計（端の駒の力ありのとき）・相手の王を返したか（隠し王ありのとき）。CPU 対戦は自分、2 人対戦は両者
- CPU は全設定共通の 2 手読み（自分の (ダメージ＋回復) − 相手の最善応手の (ダメージ＋回復)、同点はランダム。ダメージは端の駒の上乗せ込み）。隠し王では相手の王の「候補」（期限内に置かれ、まだ返されていない駒）だけを見て罰の期待値を足し、自分の王を返される応手には罰を足す
- 終局判定: 体力 0 で即負け（隠し王の罰が即負けなら、王を返された時点でも負け）。手数上限・両者パスで終わったら 体力 → 石数 の多い方の勝ち

## オンライン対戦サーバーと Cloudflare での公開（`server/`）

Cloudflare Workers + Durable Objects の対戦サーバー（招待リンク方式、1 部屋 = 1 Durable Object）。手は `web/src/engine` で検証し、相手の隠し王は送らない。画面はメニューの「マルチ」→「オンライン」から使う（上の「オンライン対戦」）。通信仕様と設計、画面側の挙動は `.agent/online-protocol.md`。

1 つの Worker（`server/wrangler.jsonc`、名前 `kyosho`、公開先 https://kyosho.rukiharukichi.com/ ）が、画面（`web/dist` の静的アセット）と API・WebSocket（`/api` の下）を同じオリジンで配信する。`/api` 以外は静的アセットがそのまま返し、Worker も Durable Object も起こさない。GitHub Pages の公開版（上記）は当面そのまま残す（Cloudflare 側の配信を本番で確かめてから止める）。

| 用途 | コマンド（`server/` で実行。先に `web/` と `server/` で `npm ci`） |
|---|---|
| 本番と同じ構成でローカル起動（web をビルドしてから http://localhost:8787 で画面と `/api`） | `npm run dev` |
| 2 クライアントで 1 局を通す | `node scripts/play.mjs http://localhost:8787`（第 2 引数でプリセット。既定は `std`） |
| 型チェック / テスト | `npm run typecheck` / `npm test` |
| デプロイの確認（web をビルドして `wrangler deploy --dry-run`。何も送らない） | `npm run deploy:check` |
| デプロイ（web をビルドしてから `wrangler deploy`。Cloudflare へのログインが必要） | `npx wrangler login` → `npm run deploy` |

### ローカル開発

- 本番と同じ構成で確かめる: `cd server && npm run dev` → http://localhost:8787/ （画面は起動時のビルド。画面を直したら起動し直す）
- 画面を直しながら開発する: 上の `npm run dev` を動かしたまま、別の端末で `cd web && npm run dev` → http://localhost:5173/ 。Vite が `/api`（HTTP と WebSocket）を :8787 に渡す（`web/vite.config.ts` の `server.proxy`）
- 本番では同じオリジンからの接続だけを受ける（`server/wrangler.jsonc` の `ALLOWED_ORIGINS` は `https://kyosho.rukiharukichi.com` だけ）。ローカルの `npm run dev` は `--var` でこれを `http://localhost:*` / `http://127.0.0.1:*` に置き換える

### 独自ドメイン（kyosho.rukiharukichi.com）

ドメイン `rukiharukichi.com` は Cloudflare Registrar で購入済み（DNS も同じアカウント）。ゲームはサブドメイン `kyosho.rukiharukichi.com` で配信し、ルートの `rukiharukichi.com` はほかの用途に空けておく（Worker の設定に足さない）。

1. 設定は済んでいる: `server/wrangler.jsonc` の `"routes": [{ "pattern": "kyosho.rukiharukichi.com", "custom_domain": true }]` と `ALLOWED_ORIGINS`
2. `cd server && npx wrangler login && npm run deploy`（または Secret を登録して main へマージし、CI がデプロイ）。最初のデプロイで Cloudflare が `kyosho` の DNS レコードと証明書を自動で作る。同じ名前の DNS レコードが先にあると失敗するので、ダッシュボードの DNS で `kyosho` のレコードがないことを確かめておく
3. https://kyosho.rukiharukichi.com/ で画面、https://kyosho.rukiharukichi.com/api/health で `{"ok":true}` を確かめる（証明書の発行に数分かかることがある）
4. ドメインを変えるときは `routes` の `pattern` と `ALLOWED_ORIGINS` の 2 か所を直す

### CI からの自動デプロイ（`.github/workflows/deploy.yml`）

main への push で web と server のテスト → web のビルド → `wrangler deploy`。PR ではテストと `--dry-run` だけ。リポジトリの Secret が未設定のうちはデプロイを飛ばして成功で終わる。

- `CLOUDFLARE_API_TOKEN`（必須）: Cloudflare のダッシュボードの「API トークン」で、テンプレート「Edit Cloudflare Workers」から作る。対象のアカウントは自分のもの、ゾーンは `rukiharukichi.com` に絞る
- `CLOUDFLARE_ACCOUNT_ID`（任意）: トークンが複数のアカウントにまたがるときだけ要る
