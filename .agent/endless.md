# エンドレスマッチ（engine/endless.ts・server/src/endless.ts）

CPU に勝つたびに CPU が強くなり、負けたら終わる。連勝数を全員のランキングで競う。決めたのはユーザー（2026-10-16〜17）: ランキングは全員分・CPU の手はサーバーが打つ・短い対局・強くなり方（体力の差 → 読みの強さ、段階のあいだは確率で混ぜる）・中断と再開・引き分けは同じ段階・記録は端末ごと。通信と画面は `.agent/online-protocol.md`「エンドレスマッチ」、ルールの本文は `RULES.md`「エンドレスマッチ（短い対局）」。

## 極（プレイヤーにだけ配る強化版のカード）

2026-10-23 にユーザーの指定で足した。プレイヤーに配る 3 枚のうち 1 枚を `ENDLESS_EX_CHANCE`（5%）で極にする（`markEx`）。配り直しの 3 枚にも同じ確率で付き（`endlessReroll`。極を配り直すと手放す）、極が出なければ必ず配り直す人でも 1 局で 1 − 0.95² ≈ 9.75%（ユーザーの「10 局に 1 回」「配り直しでも出るように、その分確率を調整」）。CPU には付けない。

極はゲージの長さが半分（`cardLength` / `sideMax`）で、効果は 応急手当 +12・大回復 +40・強打 ×2.5・補充 同じ種類を 2 つ・鉄壁 ダメージ 0・偵察 王と副将の両方・王の移し替え 盤のどこへでも・連続行動 2 手目も全部・運命の輪 引いた効果が極。全方向はゲージだけ（`engine/skills.ts` の `EX_*`。値はユーザーが承認した案）。

## 段階の表（`ENDLESS_STAGES`、36 段）

添字 = それまでの連勝数（Lv = 添字 + 1）。CPU の手番ごとに `cpuOf` が `mix` の確率で `next`、それ以外は `base` を使う。

| 段階（連勝数） | CPU |
|---|---|
| 0〜9 | イージー。CPU の体力 −27 から 3 ずつ戻して 0 まで |
| 10〜17 | イージー → ノーマルを 1/8 ずつ（17 はノーマルだけ） |
| 18〜25 | ノーマル → ハードを 1/8 ずつ（25 はハードだけ） |
| 26〜29 | ハード → 深く読む CPU 予算 300 を 1/4 ずつ（29 は 300 だけ） |
| 30〜35 | 予算 300 → 1000 → 3000 → 10000 を半分ずつ（35 は 10000 だけ） |
| 36〜 | 予算 10000 のまま、CPU の体力を 1 段階ごとに +7（`ENDLESS_TAIL_HP`） |

- 2026-10-22 にユーザーが狙いを決め直した: 公開して作者が 8 連勝（前の 32 段の表で 2 手読みの見立ての平均 7.6 とほぼ同じ）で「思ったより CPU が強い・人間はそんなに強くない」。人間の上手い人 ＝ 2 手読み（normal）、初めての人 ＝ イージーに見立てる。いったん上手い人 20・初めての人 5 を狙った 58 段の表（イージーの体力差 −31 から 1 ずつ 32 段。easy 4.94・normal 21.11）にした
- 2026-10-23 に「ちょっと長すぎる」でイージーの段を 16 段（−30 から 2 ずつ。easy 4.03・normal 13.33）にし、続けて「イージーも 10 段くらいでいい」で 10 段（−27 から 3 ずつ）にした。上手い人の見込みは 9.6 で、最初の狙いの 20 より短い（ユーザーの選択）
- 混ぜる段を細かくしても見込みはほとんど伸びない（見立ての勝率が 8 割台の区間は、段を足しても生き残りが掛け算で減る）。伸ばすには見立てがほぼ勝つ段を長くするしかない

## 未解決・ユーザーに見てもらう点

- 段階の名前は画面では「Lv N」だけ（CPU の名札の title に「イージー 体力−27」「ノーマルとハード」「深読み4 体力+14」）。CPU の強さを名前で見せるかは試遊で
- 人間の強さと CPU の見立ての対応は分からない。本番で集まる連勝数の分布を見て、表を直す（表を変えても、対局の途中の段階は挑戦の記録に写したものを使う）
- 1 手 45 秒を数えるのはつながっている間だけ（切断で止める）。切断して考える時間を稼ぐことはできるが、盤は見えない
- 本番は 2026-10-22 に Workers の無料プランのままフラグを on にした（ユーザーの判断）。入口の Worker の CPU 10ms の制限は振り分けだけなので効かず、深く読む CPU は Durable Object の中（CPU は無料でも 1 リクエスト 30 秒）。効くのは無料の 1 日の上限（UTC 0 時に戻る）: DO のリクエスト 10 万（WebSocket の受信・alarm を含む）・時間 13,000 GB-s・SQLite の書き込み 10 万行・入口の Worker のリクエスト 10 万。1 局あたり数十なので 1 日 1,000 局前後までの見込み（手元の見積もり）。超えるとその日はエンドレスとオンライン対戦が失敗するので、ダッシュボードの使用量を見て近づいたら有料に上げる
- 本番の Durable Object で予算 10000 の 1 手の時間を測る（このマシンの workerd で中央値 107ms）
