# エンドレスマッチ（engine/endless.ts・server/src/endless.ts）

CPU に勝つたびに CPU が強くなり、負けたら終わる。連勝数を全員のランキングで競う。決めたのはユーザー（2026-10-16〜17）: ランキングは全員分・CPU の手はサーバーが打つ・短い対局・強くなり方（体力の差 → 読みの強さ、段階のあいだは確率で混ぜる）・中断と再開・引き分けは同じ段階・記録は端末ごと。通信と画面は `.agent/online-protocol.md`「エンドレスマッチ」、ルールの本文は `RULES.md`「エンドレスマッチ（短い対局）」。

## 短い対局

標準（id `skill`）から体力 72・67、駒 13 個（歩4・横4・角2・飛2・金1）、ゲージの長さ 0.4 倍（`RuleSet.gauge` = 40）、巻き戻しを配らない（`RuleSet.omit` = `["judge"]`。運命の輪も引かない）。値はユーザーが承認した測定（2 手読み同士: 手数は標準の 53%・先手 49.5%・スキル 1.04 回/人。候補 d72-g04）。`gauge` と `omit` はエンドレスだけが使い、URL・設定・`PRESETS` には載せない（`sameRules` は比べるので、どのプリセットとも一致しない。サーバーの部屋の `parseRules` は URL の形に直すと落ちるので通さない）。

## 段階の表（`ENDLESS_STAGES`、39 段）

添字 = それまでの連勝数（Lv = 添字 + 1）。CPU の手番ごとに `cpuOf` が `mix` の確率で `next`、それ以外は `base` を使う。

| 段階（連勝数） | CPU |
|---|---|
| 0〜12 | イージー。CPU の体力 −36 から 3 ずつ戻して 0 まで |
| 13〜20 | イージー → ノーマルを 1/8 ずつ（20 はノーマルだけ） |
| 21〜28 | ノーマル → ハードを 1/8 ずつ（28 はハードだけ） |
| 29〜32 | ハード → 深く読む CPU 予算 300 を 1/4 ずつ（32 は 300 だけ） |
| 33〜38 | 予算 300 → 1000 → 3000 → 10000 を半分ずつ（38 は 10000 だけ） |
| 39〜 | 予算 10000 のまま、CPU の体力を 1 段階ごとに +6（`ENDLESS_TAIL_HP`） |

- 予算 30000 以上は使わない（10000 に負け越す未解決。`.agent/deep-cpu.md`）
- 先手と後手は 1 局ごとに入れ替える（奇数局はプレイヤーが先手）。測定も同じ（偶数局 i はプレイヤーが先手）

## 測定（`npm run balance -- endless 400 <プレイヤー> 0-38`、2026-10-17）

- v2 では hard が normal とほとんど変わらなかった（8.73）。序盤のイージーとの対局は短い対局の運（王・副将の罰、配られたカード）で負けることがあり、腕で避けにくい（イージー 体力 0 の段で normal 81.8%・hard 82.0%・deep:1000 96.0%）。差が付くのはノーマル・ハードを混ぜる区間（ノーマルだけの段で normal 45.8%・hard 69.3%・deep:1000 86.8%）なので、v3 はその区間を 1/8 ずつに細かくして長くし、序盤も 3 ずつにした（v2 の実測を補間した見積もりで normal 10.5・deep:1000 18.5）
- 同じ CPU の組み合わせは同じ種で同じ結果になる（v1 の段階 8 と v2 の段階 13 はどちらもノーマルだけで 45.8%）

## 未解決・ユーザーに見てもらう点

- 段階の名前は画面では「Lv N」だけ（CPU の名札の title に「イージー 体力−36」「ノーマルとハード」「深読み4 体力+12」）。CPU の強さを名前で見せるかは試遊で
- 人間の強さと CPU の見立ての対応は分からない。本番で集まる連勝数の分布を見て、表を直す（表を変えても、対局の途中の段階は挑戦の記録に写したものを使う）
- 1 手 45 秒を数えるのはつながっている間だけ（切断で止める）。切断して考える時間を稼ぐことはできるが、盤は見えない
- 本番の Durable Object で予算 10000 の 1 手の時間を測り直す（このマシンの workerd で中央値 107ms）。有料プランに上げてからフラグを on にする
